# Autoqqpet（QQ 宠物自动托管）

一个 **libxposed / LSPosed** 模块，用于自动化 QQ 宠物。它会按"有效属性收益"来规划每天的
学习 / 工作 / 冒险，兼顾疲劳度并让金币自给自足；同时处理喂食、洗澡、购买食物、PK 与访问好友。
模块还带一个保活前台服务：实时状态通知（正在做什么 / 多久前心跳 / 多久后下次唤醒）+ 看门狗，
在 QQ 被系统杀掉冻结、或调度循环卡住时自动接回，不用你守着。

> ⚠️ 实验性工具。自动化游戏可能违反用户协议并带来账号风险，请自行评估、自担风险。

## 运行环境
- 框架：**LSPosed** 或 **Vector**（libxposed API 102，静态作用域 staticScope）
- 系统：Android 8.0 及以上（minSdk 26）
- 目标应用：**com.tencent.mobileqq**（QQ 9.3.75 已真机验证；9.3.70 / 9.3.65 的入口发现与调用路径未变，9.3.65 因本机已升级未回归实测）
- 适配策略：宠物模块内部的类名会随 QQ 版本变（发包入口：9.3.65 `delegate.l` → 9.3.70 `delegate.m` → 9.3.75 可读名 `delegate.QQPetPbDelegate`）。
  本模块**不写死类名**：按方法签名自动发现发包入口并选对可用的运行时环境；若适配不上，通知栏会直接提示而不是默默不干活。

## 使用步骤
1. 安装并激活 LSPosed / Vector 框架；
2. 安装本模块 APK；
3. 在框架中启用本模块，并把作用域设为 **QQ（com.tencent.mobileqq）**（已为你预勾选）；
4. 打开 **Autoqqpet**，阅读并同意用户协议，选择目标属性并开启自动托管；
5. 通知栏会实时显示它在做什么；日志按天存一份，排障时直接用设置页的「反馈问题」带出来。

> 界面分两层：**主页只留高频三项**（练什么属性 / 怎么干活 / 托管开关），其余在「更多 → 设置」里：
> 在哪里打工、被雇佣提醒、保活状态、外观（跟随系统 / 浅色 / 深色）、关于。

## 功能说明
- 日程规划：按有效属性收益择优安排 学习 / 工作；冒险排在最后，学工疲惫后才去（想整天刷冒险用“只重复冒险”挡）。
  疲劳**不看拍定的时长上限**（已删除该选项），而是拿服务器每轮实读的预计收益（学习算属性/小时、打工算工分/小时）
  与今日已出现的峰值相比：**只剔除确实降效的那个时长档**（没被削的短档照做），
  全部可做档位都降了才整天只冒险，次日自动重取基准。
- 任务模式四选一：学习优先 / **工作优先**（有活先打工）/ 只重复冒险 / **自定义排班**。
- **打工方向可选**：下拉框直接从服务器读出并只列出本账号实际解得开的职业（一个按钮刷新）；**时长档位不写死也不让人预设**，
  10 分钟 / 45 分钟 / 2 小时 / 4 小时 四个档每轮全部重读，拿当时的实时数字算净收益取最划算的那个（宠物疲劳时这些数字会整体下降，写死就会选到亏本档）；
  各职业算出来相等时只说“并列”，不标“最佳”。
- 数据存放：设置与当日进度的**主存在本模块自己的数据目录**（v1.0.1 起），QQ 重装/清数据不会再带走用户配置；
  本应用不申请网络权限，除 QQ 自身的宠物协议请求外没有任何对外连接。
- 日常照顾：喂食、洗澡、购买食物（饼干 / 香皂片用完自动补货，花游戏金币）；PK 与访问好友，附带好友黑白名单与每日次数上限。
- **自定义排班**：自己定干活顺序。每一步 = 做哪一条（打工选职业再选哪一岗、学习选属性再选哪门课，也可“自动选最划算的”）
  + 做到几次或多久，做完进下一步；跑完一轮可选回到第一步或停下等明天；只有最后一步能设无限循环。
  还能写例外规则（金币不够 / 学费不够 / 体力或清洁不够 / 这一步做不了 / 已判疲劳 → 停下、去打工、去学习、去冒险、先照顾、跳过）。
  编辑器支持拖拽排序，当前执行到的那一步高亮并显示“还差多少”。
- **PK 黑白名单**：黑名单 = 不与其互动，白名单 = 只和这些人 PK，都是按昵称打勾的多选框。
  好友名册开机自动抓取，任何时候都能勾，不需要先跟谁打过；**输一次就永久进黑名单**（金币没进账就算输）。
- **每条决策都写明依据**：日志里除“选了什么”外，还给三个方向各自读到多少、被哪些原因排除、剩下最优收益；
  另有当日决策计数（如 `ADVENTURE/rate 最高×137`）。“为什么一整天只去冒险”不用再靠猜。
- **反馈问题可带诊断**：设置页一键勾选即自动附上版本、机型、设置、读数、候选与淘汰原因、当日日志；
  QQ 号、宠物 ID、好友昵称自动打码，完整日志同时复制到剪贴板。模块不上传任何数据，内容只填进你自己浏览器里的 issue 页面。
- 被雇佣提醒（**默认关**，界面里可打开）：打工进度一到 71%（这段区间的分成归被雇佣方拿大头）会弹通知，提醒去 QQ 里手动点「召回」腾回宠物。
  默认关的原因：服务器回包里“被好友雇佣”与“用户自己在 QQ 里手动开的打工”完全同形（`6400_` + 状态码 51），程序区分不了、开着就会误报；
  打开前会弹窗说清这一点，且本模块**绝不代发召回包**（服务端会拒），不开也不影响任务到点正常结算。
- 精准调度：按任务时长定点唤醒、到期准确结算、失败有界重试；短延时走进程内精确定时，避开 Doze 的闹钟节流。
  长任务（>5 分钟）**每 5 分钟会中途复查一次**：你在 QQ 里提前召回宠物时不需要白等到原定结束点，收益降效也能当场发现。
- 保活：前台服务 + 唤醒锁 + 实时状态通知 + 看门狗 + 开机自启。判活同时看「心跳是否新鲜」与
  「是否还排着未到期的唤醒」两件事，所以既能在 QQ 被杀后救回，也能在循环自己卡住时接回；
  救活动作 90 秒节流，跑 30 分钟的长任务期间不会被误判成挂死。
- **静默恢复**：发现 QQ 不在时，看门狗只把 QQ **进程**拉起来（查它导出的 ContentProvider、试绑它的后台服务），
  **不弹任何界面、不打断你当前在用的应用**，并补发一次指令接回循环。

## 永不抢前台（v1.1.0 起）
以前 Android 14 上为了在 QQ 被杀后把它**拉回前台**，需要一个可选的「显示在其他应用上层」权限做系统豁免。
v1.1.0 起这条路径**连同该权限声明一起删除了**：本模块任何时候都不会把 QQ 推到你的屏幕上，
也不再申请任何用不到的权限（以前授予过的用户升级后该授权自动失效，不影响使用）。
代价很明确：极端情况下（系统连静默唤进程都不放行）需要你点一下通知，而不是它自动恢复 ——
这是故意选的取舍：**不打扰优先于自动**。全工程本来也没有任何悬浮窗绘制代码。
